# Daily archive locker

The locker leads with **From the archives**: one older approved meme, a visual description, and a curated fictional punchline. The full searchable/filterable collection remains available inside a closed disclosure. Recaps and their dated artwork are unchanged.

## Source and intake

The owner's private source folder is `nhl fantesy images` in the Obsidian vault. Never deploy the vault or enumerate its private paths in the website. Inspect actual pixels before writing a description: a filename alone is not evidence of the content, character labels, or publication suitability.

Only explicitly approved derivatives in the public editorial catalog may be featured. `src/data/archive-features.json` is a separate curated allowlist; new daily recap artwork is **not** automatically enrolled. The initial pool contains two already-approved older images (#05 and #10). #10 is the previously approved robot/monkey scene from the named vault folder. This is a small starter pool, not an import of the entire vault. More vault images require screening and explicit owner approval before adding public assets/catalog records and a feature entry.

Each feature entry has `memeId`, `title`, `description`, and `joke`. Write descriptions of visible actions, not guessed identities or invented events. Approved manager mappings may be used; never identify people by face. Keep political material, outsiders and private material out of this pool. The initial selector admits only evergreen art without score context, so old scored images cannot look like current results.

## Selection and rollover

`buildArchivePool` intersects the curated list with the approved catalog and rejects pending, dated, scored, duplicate, or nonlocal candidates. The page also verifies the asset exists before constructing its pool.

`pickArchive` uses a fixed shuffled order and the America/Phoenix calendar date. Everyone sees the same selection for a date. With an unchanged pool, every item appears once per cycle before repetition. Two starters repeat after two days; adding more approved classics increases the cycle. It is deterministic shuffled rotation, not live random model selection. Pool changes can change today's selection.

The static page includes a build-time fallback. Its bundled browser script picks for the visitor's current Arizona date on load, checks every minute, and checks when the tab becomes visible. It therefore advances without a cron, ESPN request, API, account, local storage, or daily redeploy. JavaScript-disabled visitors see a clearly disclosed last-build selection. Descriptions/jokes are curated at image intake, not generated by a paid image service or model on every page load.

## Verification

Run build before tests that inspect dist; do not build concurrently in this worktree.

```sh
BASE_PATH=/fantasy-family/ ASTRO_TELEMETRY_DISABLED=1 npm run build
npm test
python3 -W ignore -m unittest discover -s scripts -p 'test_*.py'
```

Unit tests cover Arizona midnight, stable same-day selection, order independence, exhaustion before repeats, empty/single pools, invalid clock/IDs, and approval gating. Browser QA should verify mobile overflow, complete images, real runtime midnight rollover, and the collection's search/filter/reset after opening the disclosure. No changes to the review-packet runtime or recurring publication jobs are necessary for this feature.

Publication of this redesign is a separate owner decision; a local preview and successful tests are not a live deployment.
